# 05 · 图片工作流

## 1. 用户视角：永远只需"放文件"或"说一句话"

| 用户想做什么 | 用户动作 | 其余由 AI 做 |
|---|---|---|
| 首次收录 | 什么都不用做 | AI 压缩已有 6 个作品的 24 张图 |
| 加新作品 | 把图片放进 `朱翰林的建筑作品\N.作品名\`（自建子文件夹） | 压缩、命名、建详情页、首页加卡片、更新对照表 |
| 换某张图 | 新图放进素材文件夹，告诉 AI「把作品X第N张图换成新的」 | 压缩并覆盖 images/project-NN/NN.jpg、同步图注 |
| 改文字 | 告诉 AI 要改什么 | 改 HTML |
| 发布更新 | 告诉 AI「发布到网上」 | 部署 |

## 2. 命名约定（铁律）

- 每作品一个文件夹 `images/project-NN/`，NN 与页面文件 `project-NN.html` 一一对应
- 图片名两位数字＝页面出现顺序：**01.jpg 固定为首页封面**；02.jpg 起为详情页顺序
- 每张图两份输出：`NN.jpg` 完整版（详情页/灯箱）＋ `cover-NN.jpg` 4:3 封面版（首页卡片）
- 原始图只读保留在原文件夹，永不覆盖

## 3. 压缩与裁剪参数（tools/compress.ps1）

| 输出 | 参数 |
|---|---|
| 完整版 NN.jpg | 铺 #F9F9F7 底 → 长边 3000px → JPG q85 sRGB → ≤500KB |
| 封面版 cover-NN.jpg | 居中裁剪 4:3 → 1200px → q85 → ≤200KB |
| 占位图 | halftone 半调纹理 JPG <60KB |

## 4. 对用户的素材建议（写入 README）

- 格式 JPG/PNG 均可；长边 ≥3000px 更好；单张 ≤20MB
- 透明底 PNG 没问题，脚本自动铺米白底
- 图纸文字越小越需要大原图（压缩后 3000px 长边通常够看清）

## 5. 对照表维护规则

- README 维护「文件 ↔ FIG 编号 ↔ 内容」对照表
- AI 每次换图/加图后必须同步更新对照表与对应图注
